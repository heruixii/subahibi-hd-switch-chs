## 一、部署链路（本轮最大收获）

真机上多次失败后定位出三条硬事实，并据此改写工具链：

| 事实 | 后果 |
|---|---|
| Shell `CopyHere` 无法替换 MTP 上已存在的同名文件 | 会先删掉旧对象再静默失败，**文件凭空消失且不报错** |
| `IPortableDeviceContent::Delete` 设备侧删除成功但可能回 `0x80070079 ERROR_SEM_TIMEOUT` | 不能以 HRESULT 判成败，必须以枚举结果为准 |
| Shell 的设备→PC 回读（CopyHere from device）不可用 | 回读必须走 WPD 直读 |
| `GetStream(STGM_READWRITE)` 就地覆盖回 `0x80070057` | 设备不支持原地写，只能删+建 |

新工具 `D:\sbtools\p1479\p1479.exe`（源码 `03_脚本工作区\P1479_第317轮_部署m22覆盖层\p1479_wpd_swap.cpp`）：
`ls` / `del <name> <bytes>` / `put <name> <src>` / `get <name> <dst>` / `overwrite`（设备不支持）。
编译：`g++ -O2 -std=c++17 -municode ... -lole32 -loleaut32 -luuid -lpropsys C:/Windows/System32/PortableDeviceApi.dll`

**固定部署流程**：`del` 旧覆盖层（尺寸必须匹配）→ `put` 新覆盖层（只新增）→ `get` 全文件回读 → SHA256 比对。

## 四、抽样纠错（本轮启动）

结构检查（13,702 条）：引号不配对 764 / 长度比异常 125 / 引号风格差异 50 / 句末句号丢失 28 / 保留日文汉字 8 —— 绝大多数是**检查器误判**（日文原文本身就是截断句，中文照截断），无系统性语义问题。

语义抽样（seed 20261111，100 条 + m18 层单独 60 条）发现问题：

- **m18 老层（overlay_manual4，10,418 条）质量明显偏低**，30 条里 6~8 条错译，典型：
  - `死ぬの何か恐くない` → 「死什么的不可怕吗」**反问方向反了**
  - `つー話しているし、まぁ、間違いではないかもなぁ` → 「我若一遍又一遍将其重复，也怎能以其为错误」**完全跑题**
  - `どれだけの女の子の気持ちをくじかせたか` → 「让多少女生着迷」**くじく=挫伤，反义**
  - `ソール・クリプニ` → 「索尔·克里普斯」应为**克里普克**
  - `い、入れてくれないかなぁ` → 「喂，可以了吗」**丢失"插进来"**
  - 出现「（笑笑注：高达梗）」这类**译者注混入正文**
- 本轮新译层（b21~b26，3,284 条）抽样未见错译。

结论：纠错必须按**消息出现权重**排序做，优先修高频行；m18 层是主战场。
