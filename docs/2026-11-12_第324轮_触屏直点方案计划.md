# P1491 触屏直点方案（计划）

日期：2026-11-12
目标：让玩家**用手指直接点**（点哪里点哪里），绕开"右摇杆积分移动光标"带来的帧率相关顿挫。

---

## 1. 为什么触屏能真正解决问题

现在的链路是：右摇杆 → 每帧积分位移 → 整数坐标 → 绘制。**光标每秒只能被改写「帧数」次**，帧率一低必然一跳一跳，这是物理上限，调算法只能缓和不能消除。

触屏是**绝对定位**：手指在哪，命中点就在哪，不依赖逐帧积分。顿挫问题从根上消失。

---

## 2. 现状（已确认的事实）

| 项 | 事实 |
|---|---|
| 渲染 | SDL2 + EGL/GLES2，输出层先合成 8 子窗口，再画光标，最后 Present |
| 逻辑坐标 | 1280×960（原 GPL2 画布），屏幕上是 4:3 letterbox，映射在 `P441Viewport.destination` |
| 点击路径 | 引擎用 SDL 鼠标事件（`SDL_MOUSEBUTTONDOWN/UP`）+ `OS_CursorGetPos`；手柄点击由 `p907_mouse` 合成 SDL 事件注入 |
| 光标绘制 | `p1409` 的 `P1078_RenderLivePhysicalCursor`，每帧在输出层画 |
| 触摸代码 | **当前工程里没有任何触摸实现**（全库搜 `SDL_FINGER` / `hidGetTouchScreenStates` 均无命中） |
| 构建 | `p1460` 重建基线 → 188 个目标 → GNU 链接 → elf2nro，已跑通（配 ASCII 输出 shim） |

结论：触摸要从零加，但注入路径可以复用现有的"合成 SDL 鼠标事件"机制。

---

## 3. 两个取点方案

### 方案 A：libnx 直接读（推荐）

```c
hidGetTouchScreenStates(&state, 1);   /* 每帧轮询 */
state.count > 0 → state.touches[0].x / .y   /* 物理帧缓冲坐标 */
```

- 优点：确定性最强，不依赖 SDL2 后端有没有实现触摸事件；每帧读一次，和光标绘制同一节奏
- 缺点：需要 `#include <switch.h>` 和一次性 `hidInitializeTouchScreen()`；不能与 SDL 的 hid 初始化冲突（需要实测）
- 坐标：libnx 给的是**物理屏幕坐标**（掌机 1280×720）

### 方案 B：SDL 触摸事件

监听 `SDL_FINGERDOWN / SDL_FINGERMOTION / SDL_FINGERUP`。

- 优点：走 SDL 抽象，不用碰 libnx
- 缺点：**取决于这套 SDL2 的 Switch 后端是否实现了触摸**，工程内无先例，风险更高

**采用 A**，B 作为 A 失败时的备选。

## 4. 坐标映射（关键，决定"点得准不准"）

libnx 给物理坐标 `(tx,ty)`，渲染器画在 `vp->destination = {x,y,w,h}`：

```
if tx < dest.x or tx >= dest.x+dest.w or ty < dest.y or ty >= dest.y+dest.h:
    忽略（点在黑边上）
logical_x = (tx - dest.x) * 1280 / dest.w
logical_y = (ty - dest.y) * 960  / dest.h
```

这套换算与 `OS_ClientToScreen` 的逆运算一致，正是引擎命中测试用的坐标系。
**验收必须验证"点哪里就命中哪里"**，尤其是屏幕四个角和存档槽边界。

## 5. 事件注入

复用现有 `p907_mouse` 的合成路径，不新开一条：

| 触摸状态 | 动作 |
|---|---|
| 手指按下（count 0→1） | 光标移到该点 → 注入 `SDL_MOUSEMOTION` + `SDL_MOUSEBUTTONDOWN` (left) |
| 手指移动 | 光标跟随 → 注入 `SDL_MOUSEMOTION`（同一帧内合并，只发最后一次） |
| 手指抬起（1→0） | 注入 `SDL_MOUSEBUTTONUP` |
| 第二根手指 | 忽略（避免误触），或留给"右键/存档界面返回"（后续可选） |

注入用 `SDL_PushEvent()`，由原有事件泵（P438）取走，BGI 鼠标层不需要任何改动。

## 6. 与手柄共存 & 使用场景

| 场景 | 行为 |
|---|---|
| 掌机模式 + 触屏 | 手指按下期间，光标由触摸接管；抬起后交还手柄 |
| 底座模式（无触摸） | `hidGetTouchScreenStates` 恒返回 0，自动退回纯手柄，行为与现在一致 |
| 触屏同时推摇杆 | 以触摸为准（手指按下时屏蔽摇杆位移），避免两个源打架 |

**注意**：底座模式没有触摸，摇杆方案必须保留，触屏是"增强"不是"替换"。

## 8. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| `hidInitializeTouchScreen()` 与 SDL 的 hid 初始化冲突 | 触摸读不到，或影响手柄 | 首次失败即永久关闭触摸路径，手柄不受影响；实测确认 |
| 触摸坐标与 viewport 缩放不一致 | 点偏 | 四角 + 九宫格实测校准；必要时按实测加偏移 |
| 触摸事件与手柄合成的鼠标事件同帧冲突 | 双击、误点 | 触摸按下期间屏蔽手柄位移与点击 |
| 掌机模式下系统手势区（底部边缘） | 边缘点不到 | 已知限制，测试时标注 |
| 只改 1 个对象 | 风险面小 | 但注入逻辑若放错层（例如事件被引擎丢弃）需换注入点，可能多一轮 |

## 9. 验收清单

1. 掌机模式，手指点标题界面「开始游戏」→ 直接进入
2. 点对话框 → 文本推进（等于 A 键）
3. 打开存档界面 → 点存档槽 → 槽位被选中（验证坐标精度）
4. 点屏幕四角 → 命中位置与视觉一致，无明显偏移
5. 底座模式（或遮住触摸）→ 手柄照常可用
6. 手指按下时推摇杆 → 光标不抖、不跳
7. 长按拖动 → 光标跟手，无残影
