# P1486 主页磁贴方案：结论为不可行（本机）

日期：2026-11-12
设备：真实 Switch，MTP 由 DBI 提供（挂载点 `1: SD Card` / `5: SD Card install` / `6: NAND install` / `7: Saves` / `8: Album`）

## 目标

让移植版出现在**系统主页游戏列表**里，点磁贴直接启动，而不是每次进 hbmenu 选 NRO。

## 走过的路

| 步骤 | 结果 |
|---|---|
| 1. 给 NRO 加 ASET（256×256 图标 + control.nacp，名称「素晴日 HD 汉化版」/ 发布者 ALTIRKIE / 版本 1.0.0） | 结构校验通过，**未实机验证**（NRO 开头有 0x20 字节 `HOMEBREW` 前导头，hbmenu 能否识别文件尾的 ASET 无法离线确认） |
| 2. Nro2Nsp 3.3.5 GUI 自动化填表 | Title Id 手动填 `05000A0000000000` 被它自己的校验拒绝（虽满足"05 开头 / 0000 结尾 / 16 位"），必须点 `Randomize`；模式单选按钮只能靠 `SelectionItemPattern.Select()` 选中 |
| 3. 直接调用它展开出来的 hacbrewpack v3.00（绕过 GUI） | 成功产出 NSP（708,312 B，3 个 NCA），**无 ticket**（`eticket_rsa_kek*` 全部 Failed to match） |
| 4. 装到本机测试 | **"无法启动软件"** |
| 5. 改 `--plaintext` 重建（NCA 不加密、不需要 title key） | 仍然 **"无法启动软件"** |
| 6. 对照实验：装 Nro2Nsp 自己生成的原生 NSP（05C9151E09A60000，结构与我们完全相同：3 个 NCA、无 ticket） | 仍然 **"无法启动软件"** |

## 结论

**Nro2Nsp 3.3.5 这一代工具的产物在本机无法启动**，与是否手工调用 hacbrewpack 无关，与有无 ticket 也无关（两者产物结构一致，且用户机器上别的自制 NSP——植物大战僵尸——可以正常启动，说明签名补丁是生效的）。

最可能的原因（未进一步验证）：该工具 3.3.5 是按固件 9.0.0 重编的，产出的 NCA header / ACID / NPDM 在本机较新的系统版本上过不了 loader 校验；也可能与它固定的 SDK 版本 / keygeneration 有关。

## 处置

- SD 上的测试包已删除（`chs` 字典与 NRO 未动）
- 系统里装上的两个标题（旧包一个 + 探针一个）需在 **系统设置 → 数据管理 → 管理软件** 手动删除
- **启动方式维持 hbmenu**，汉化内容不受影响（覆盖层已是最新版）

## 如果以后还想做磁贴

需要换一条工具链，候选：

| 方案 | 前提 |
|---|---|
| 更新版 Nro2Nsp / 其它 forwarder 生成器（如 Switch Army Knife、sphaira 自带功能） | 需支持当前固件版本的 NPDM/ACID |
| 用 devkitPro + hacpack 手工构建并**签名** NSP | 需要完整 keyset（含 `eticket_rsa_*`）并能正确签 NCA header |
| 直接在 NRO 层解决（hbmenu 内显示图标/名称） | 已完成：P1482 的 icon + nacp，P1483 的 ASET 追加工具 |
