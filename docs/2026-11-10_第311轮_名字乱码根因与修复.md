# 第311轮：名字乱码根因确认与修复（P1123→P1125）

日期：2026-11-10。

## 一、根因（有实机截图与日志双证）

名字牌用**日文原字符串**（未被翻译），但绘制时正文的"中文模式"还开着，于是：

| 名字 | 原字节（CP932） | 被当 GBK 解出 | 实机表现 |
|---|---|---|---|
| 卓司 | `91EC 8E69` | 戩巌 | 截图里的「戩巌」 |
| 由岐 | `9752 8AF2` | 桼婒 | 同型 |

不是缺字、不是花屏、不是字体缺失——是**解码表用错**。

## 二、字体层的关键事实（P1475 日志实测）

| 用途 | `OsFont_t` 高度 | 宽度 | 字节 |
|---|---:|---:|---|
| 名字牌 | **152** | 76 | `9752 8AF2` / `91EC 8E69` |
| 正文 | **136** | 68 | GBK 中文 |
| 光标 ▼ | 136 | 68 | `81A5` |

所有字体本质都是同一份 Noto（`OS_FontOpen` 忽略 face 名，只按高度缩放），差异只在字号。

## 三、修法（改在 `p975` 的 OS 字体层，可替换对象）

```c
int body = (f->height == 136);          // 只有正文字号承载译文
if (len==2 && s[0]==0x81 && s[1] in 0x9f..0xbf) forcecp = 1;   // ▼ 等 CP932 符号
if (len==1 && s[0]==0x0c) { use="\x81\xa5"; forcecp = 1; }      // 旧文字光标 → ▼
if (forcecp || (old && !body && len>=2)) P546_SetChineseLegacyMode(0);
p523_render(f, use, uselen, ...);
P546_SetChineseLegacyMode(old);         // 恢复
```

要点：按**字号**区分"译文"与"原文"，而不是按字节特征——因为名字本身就是合法 CP932，任何字节启发式都抓不到。
