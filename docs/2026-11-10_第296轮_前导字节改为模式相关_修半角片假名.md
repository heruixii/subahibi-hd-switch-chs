# 第296轮：把"全局放宽前导字节"改成"按中文模式放宽"（修半角片假名回归）

日期：2026-11-10。设备已换 P1115。

## 一、发现的回归风险

第288轮的 3 字节补丁把所有 0xA1–0xDF 都当成双字节前导，中文能显示，但**日文里的半角片假名**（0xA1–0xDF 单字节）会被误拆。

扫描 130 个场景反汇编，`push_string` 中出现半角片假名的**实际显示文本有 15 条**，集中在 `1-2_0715.bsd` 的网络用语/颜文字段落，例如：

```
個人情報ﾜﾛｽ。なんで体重身長まで知ってるwwwwwww
デムパｷﾀー
ビックﾊｻﾞｰﾄﾞこっちくんな
　⊂　    ﾉ　　( ´∀｀)/
```

这些在旧补丁下会变成乱码。

## 二、改成模式相关

直接重编 `src/core/strutil.c`（150 对象集里的 `src_core_strutil_aarch64.o`，原件备份 `.PRISTINE_BACKUP`）：

```c
extern int P546_ChineseLegacyMode(void);
int SjisIsLead(uint8_t c)
{
    if(c < 0x80) return 0;
    if(P546_ChineseLegacyMode()) return c < 0xff;   /* GBK 0x81..0xFE */
    if(c < 0xa0) return 1;
    return c >= 0xe0;                               /* 原 CP932 */
}
```

- 中文模式只在 WaitText 绘制译文、以及窗口文字入口判定为 GBK 时短暂开启；
- 日文（含半角片假名）在模式关闭时走原 CP932 路径，不再被误拆；
- `TextIsWide` 仍按字节长度判宽，中文模式下的双字节仍是全角。
