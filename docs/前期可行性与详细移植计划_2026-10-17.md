# 《素晴日》PC 全语音 HD 版 → Nintendo Switch：移植可行性与详细实施计划

- 评估日期：2026-10-17
- 来源目录：`D:\switch游戏\素晴日\素晴日整合\1.游戏合集`
- 工作原则：此轮仅做只读探测与方案，不覆盖 PC/NS 游戏本体，不安装工具，不修改或打包发布游戏内容。
- 证据性质：本地已读取实际目录、文件头、BGI ARC20/ONS NSA 索引，并在内存解码旧 ONS 脚本；没有实际在 Switch 上运行 HD 资源，也尚未逐帧比对图片和音频内容。

## 0. 结论（先读）

**推荐方案：沿用已存在的 ONScripter Switch 端和旧版完整中文脚本，分阶段替换 PC HD 资源，再移植新版独有脚本/后日谈。**

技术判断：
1. 旧版高清化/音画增强：**可行性高（有条件）**。旧版和 HD 命名一致性很高，且老版脚本已经成功可逆识别，适合自动批量转换、保留原逻辑。
2. 补齐 PC HD 新增剧情、CG、语音、演出：**可行但仍需原型验证，工作量中高**。同名剧情入口 125/130，五个未直接匹配的入口与同名脚本内部差异是优先处理对象。
3. 将 PC BGI.exe / BGI-CHS.exe 原样复制到 Switch 或把 ARC 直接换进 ONS：**不可作为有效路线**。Windows PE 和 Switch NRO 平台/指令架构不同；BGI 与 ONS 的脚本 VM 和资源格式也不同。
4. 把 BGI 整个引擎原生移植到 Switch：**目前不推荐，风险极高**。OpenBGI 公开材料明确将 Switch 列为远期/愿望目标，尚不能当成可运行此游戏的 Switch 引擎。
5. 本报告的“可行”不表示已完成移植或已确认所有新增内容能正常运行。应先以可重复的原型验收决定是否扩展。

## 1. 盘点：实际存在的文件和格式

**PC HD 源：** `...\[汉化][PC]素晴日全语音HD版[冥月汉化组]\[PC][冥月汉化组]美好的每一天～不连续的存在～ 全语音HD版`
- 引擎：`BGI.exe`、`BGI_patch.exe`/`BGI-CHS.exe`（Windows PE），`BGI.gdb`、`BGI.hvl`。
- 资源：55 个 `.arc`，头部均为 `BURIKO ARC20`；索引总条目 **39,671**。
- 剧情：`data01000.arc` 和 `data01101.arc` 至 `data01999.arc` 等 `data01*.arc` 共 **130** 个无扩展名 BGI 场景/脚本条目，读取到 `DSC FORMAT 1.00` 文件头。
- 图片：包含 `CompressedBG___` 格式，如 `data02910.arc` 的 `bg1001a`，读到 1280×960；`data02930.arc` 的 `ev0001_l` 为 3840×2880；部分立绘是其他纵横比。
- 音频：`data040*.arc` 共 **32,882** 个条目（主要与角色语音有关；不能仅根据名称保证每一项都是独立剧情语音），内部有 BGI `bw` 音频头，不能当 OGG 直接改扩展名。
- 视频：至少看到 `fsmile.mpg`、`hill.mpg`、`ed_air.mpg` 等 MPEG 内容与独立动画资源。
- PC HD 主目录、备份文件、附件及后日谈补丁合计约 **4.90 GiB**，该数字不等于最终 Switch 安装体积。

**NS 旧版源：** `...\[汉化][Switch](ons)素晴日老版 patch-V1.1.1-NSP\[Switch]素晴日老版 V1.1.1-NSP`
- `onsemu/exefs/ONScripter.nro`（20.6 MiB）、`ONSBrowser.nro`（9.4 MiB），为 Switch Homebrew NRO。
- `onsemu/suqingri/arc.nsa`：**5,221** 个 JPG/PNG 图片条目。
- `onsemu/suqingri/arc1.nsa`：**26,208** 个 OGG 音频条目。
- `onsemu/suqingri/arc2.nsa`：**191** 个 JPG/PNG 图片条目。
- NSA 三包合计 **31,620** 个内部资源条目。
- `nscript.dat`：3,809,022 字节；识别标准 XOR `0x84` 编码。仅在内存还原后使用 GB18030 无损解码，**121,701 行、689 个脚本标签**，没有替换字符；头部 `;$S800,600G2000`，表明旧脚本以 **800×600** 为逻辑坐标。
- `system.lua`：包含图片移动动画函数 `NSCOM_lmvstart` 等。
- `mpg/*.mp4`：5 个转换后视频。
- NSP 启动文件仅约 **0.33 MiB**，游戏主要资源在其外部的 `onsemu` 文件夹中，不能理解为已存在单文件完整游戏 NSP。
- 旧版的 `nscript.dat` 内可看到已将 BGI 函数/事件映射为 `f_1a5`、`f_280`、`f_300_1` 等 ONS 调用；这是进一步补译和增量迁移的良好基础。

## 2. 本地实测复用程度

基于**资源名称/标签**（不是画面像素或剧情内容相同）的对比：

| 类型 | 旧版范围 | 也存在于 PC HD | 比例 | 说明 |
|---|---:|---:|---:|---|
| 图片，不重复名称 | 5,224 | 5,147 | **98.53%** | PC HD 对应图片候选 5,483 个不重复名称；两版容器内有重名或多版本资源，必须记录来源和优先级 |
| 音频/语音文件名 | 26,208 | 25,639 | **97.83%** | PC HD `data040*.arc` 共 32,882 个条目；有不少只在 PC HD 中出现，必须单独做定位和内容核验 |

**五个暂未找到对应的 BGI 剧情/流程入口：**
1. `data01000.arc : yuzu_2g`
2. `data01801.arc : extra`
3. `data01900.arc : 8_af`

必须核实上述条目是新版追加、旧版未移植、还是被旧版改名/内联调用；尤其 `8_af` / `endafter` 需要重点关注后日谈/追加场景。**不能仅以“五处缺失”就断言只要补写五个脚本即可完成整个新版。** 125 个同名脚本内部也需逐段比对，汉化补丁和独立后日谈补丁可能进一步改写流程。

## 3. 方案取舍

### 路线 A（主推）：旧版 ONS 增量升级
保留旧版 1.1.1 的可运行 NS 端、中文剧本、菜单、Lua 动画与流程；自动提取/转码同名 HD 图片及语音、替换动画视频；对分辨率、遮罩和脚本坐标做适配；再移植追加剧情。
- 优势：底座现成；大量资源可按文件名定位；可逐段回归测试；工作量明显少于重造引擎。
- 风险：BGI 画面合成/动画与 ONS 表达不完全一致；语音与剧情映射要验证；部分高清素材耗内存；旧版原有的演出简化不会因换图自动恢复。
- 判断：最适合此目录素材的方案。

### 路线 B：直接构建 Switch 版 BGI 引擎
把 BGI 字节码虚拟机、系统脚本、渲染、声音、视频、存档全部复刻/移植到 Horizon/Homebrew。
- 风险极高，需要引擎级开发及大量逆向兼容测试；目前不建议以此作为本项目起点。

### 路线 C：重新用 Ren'Py/其他跨平台 VN 引擎制作
- 通常需要重新建立剧情命令转换、菜单 UI、CG/视频播放等，不能直接重用老 ONS 脚本；以当前目录条件看，投入收益不如路线 A。

## 4. 实施步骤与验收闸门（推荐顺序）

### P0 — 基线保护与可复现的证据清单
任务：
- 保持 `1.游戏合集` 内所有内容只读，不替换老补丁/老存档；单独建立 `work/source_indexes`、`work/ns_script`、`work/converted_assets`、`build/sdmc/onsemu/suqingri`、`qa`。
- 为 `BGI_patch.exe`、`BGI-CHS.exe`、55 个 PC ARC、3 个 NS NSA、`nscript.dat`、NRO、NSP 建文件大小、SHA256、版本登记；区分主版本与后日谈补丁版本。
- 写自动化元数据索引解析器：BGI `BURIKO ARC20` 索引（只读）与 NS NSA 索引（只读），输出结构化 CSV/JSON，记录 archive/成员名/偏移/大小/头部格式/优先级。
- 在**工作目录**解码 `nscript.dat` 为 GB18030 副本，编写 re-encode 校验：对解码后的字节 XOR 0x84 能还原与原文件 SHA256 一致；绝不覆盖旧版脚本。
- 基线测试：若可以在 Switch 上启动旧版，记录菜单、开场、存读档、语音、跳过、选项、CG 与 Home 菜单行为。
闸门：文件索引可复现、旧原件哈希未变化、旧版启动验证可回溯。未完成则不进入批量资源替换。

### P1 — 先做一个“HD 同名替换”小样，而非全量打包
任务：
- 从 HD ARC 安全提取 **5 类样本**：背景、人物立绘、CG、透明 UI、演出分层/移动用素材；要把同名不同 ARC 的版本分别保存，不能无条件覆盖。
- 验证 `CompressedBG` 转 PNG/WebP/JPG 的颜色、alpha、遮罩、位深及尺寸。对每个样本保留 PC 原貌与 NS 原版渲染对照。
- 旧版脚本 800×600；背景 CBG 实例 1280×960；Switch 物理屏幕 16:9，推荐保留 4:3 原始构图，在 1280×720 输出上以 960×720 有效画面居中显示，避免强行横向拉伸。
- 关键：保留/修正旧脚本背景移动、缩放和 sprite 坐标逻辑。**同名不同尺寸不应直接替换**；分为“保留 800×600 逻辑的贴图适配”和“把引擎及坐标整体提升”的两组对照小样，择稳定方案。
- 旧 ONScripter NRO 可能不是有 HD 选项的版本。先验证现有 NRO 的实际适配能力；替换引擎要检查脚本命令/Lua/API 是否兼容，而非直接升级。
闸门：一段开场场景能正确显示背景、立绘、文本、选项、语音；无缺字/裁切/遮罩错误；可返回菜单、存读档。

### P2 — 建立 PC→ONS 资源自动化转换流水线
任务：
- 读取 BGI ARC2 清单，解包到独立工作缓存（不破坏原 ARC）；记录压缩格式签名。
- 图像：`CompressedBG`→无损中间图→适合 Switch 的 PNG/JPG/纹理；每个同名映射给出转换状态、宽高、alpha、所属 ARC、SHA256，并让重复名有显式覆盖顺序。
- 语音：`data040*.arc` 中 BGI `bw` 音频格式先规范解码，再编码成 OGG/其它该 ONS NRO 可播格式；采样音频波形、响度、长度后对照旧 OGG，绝不只改后缀。
- 视频：从 MPEG 原始媒体转换为现有 Switch 播放路径支持的 MP4，保留实际帧率、音轨、宽高比与跳过语义；系统已有 ffmpeg/ffprobe，可用于转码检查。
- 优先建立“通用同名映射”，再收集仅 PC HD 存在的资源；生成异常清单（缺失、重名冲突、分辨率不符、无法解码、音频超长、脚本引用找不到）。
- 不一次生成最终完整包；先复用旧版文件树验证一章，确认资产命名、优先级与缓存策略后才扩大。
闸门：抽样 100% 可解码，无新增缺资源；全部旧版资源引用能解析到输出；同一构建两次得到相同映射清单。

### P3 — 剧情与追加部分兼容
任务：
- 对 PC BGI 的 130 个场景文件提取函数/流程与文本指令序列；旧版 ONS 可逆获得 121,701 行中文脚本，并含大量 BGI 风格 `f_` 函数包装。
- 建立“BGI 场景名→ONS 标签名→分支/语音/图片引用”的三向对照。先检测 125 个同名场景内容差异，再对上文五个候选缺失入口逐一处理。
- 优先分析 `8_af`、`endafter`、`extra`；核实后日谈补丁里的 **346 MiB 的 BGI-CHS.exe** 是否包含额外内容/逻辑，并记录该补丁安装依赖及覆盖行为；不能假定它只是多一个脚本文本。
- 在 ONS 中复现新增分支入口、返回标题、图库解锁、成就标记、语音时序和演出；对不能直接实现的 BGI 效果做等价表现层实现并列明降级项。
- 保持原版选项计数器、全局变量、存档槽、历史记录语义；新旧存档不默认兼容，必要时区分存档路径/版本并保留旧存档。
闸门：剧情流程图节点及分支覆盖完成、可进入新增部分、所有结局能返回/解锁、关键变量不串台。

### P4 — Switch 性能、稳定性及 UI 回归
任务：
- 对 4:3→16:9 的适配采用统一 letterbox/viewport；全屏/窗口/CG 图、触屏坐标、Joy-Con 输入逻辑一致。
- 注意 3840×2880 RGBA 图片单张解码约 **42.2 MiB** 内存，原图直接多张缓存会占用大量内存；按实际场景选择降采样与缓存淘汰，避免“高分图全部解码常驻”。
- 重点测试批量跳读、快速存取档、重进场景、连续播放视频、字幕长度/字体、多 CG 叠层、移动/变焦、睡眠唤醒、断档和长时间运行。
- 对屏幕截图进行像素/位置对照，保留中文 UI 字宽、菜单字号、颜色遮罩、角色名字、全屏 CG 可见区域。
- 验收矩阵至少包含：开场与菜单；原七个主章节/重要选项；额外剧情与后日谈；所有结局入口/返回；全局存读档；CG/音乐鉴赏；视频播放；长时间连续运行。
闸门：无可复现崩溃、严重图文错位或不完整剧情，已知降级项单列并获得确认。

### P5 — 发布方式与清理
任务：
- 保留老包和旧存档备份，另用明确的新构建目录。用 SD 卡工作目录安装/启动，先验证运行再决定是否要制作前端启动器。
- 既有 NSP 仅约 0.33 MiB，属于启动外部数据的布局；**不要宣传为下载 NSP 就能独立安装游玩**。推荐 NRO/forwarder 与 `sdmc:/onsemu/suqingri/` 外置资源组合，经实际安装测试后给出精确使用和卸载说明。
- 卸载旧版前先备份 SD 卡保存数据、原目录与旧 forwarder；新旧不复用可能冲突的游戏 ID、存档命名和图像缓存；杜绝先删除再发现回滚不可用。
- 如果准备公开 GitHub 仓库，仅保存用户有权公开的自写转换工具、差异清单模板、说明文档和有相应许可的代码；**不要上传游戏原始 ARC/NSA、声音、CG、完整剧本文本、游戏 NSP 或第三方汉化内容**，除非已得到所需权利许可。
闸门：明确版权授权范围，独立验证新建启动器是否具备可重现安装路径，写清楚依赖、版本和回滚手册。

## 5. 当前环境、依赖及成本控制

- D 盘检测剩余约 **96.74 GiB**；可以容纳抽样与中间资源，但批量提取+高清图片+视频转码+多版构建可能快速增长。第一轮转换应按 archive/章节分批处理，避免做无意义的 3 份完整副本。
- 已找到 `python`、`ffmpeg`、`ffprobe`、`git`；当前 PATH 未找到 7z、cargo/rustc、make，常见 devkitPro 路径未检出。
- 因已有 NRO 可用，P0/P1 初期不依赖 devkitPro；若必须改引擎渲染/播放功能，再决定是否布置 SDK 并单独验证许可证。
- 工具候选：GARbro 或兼容 BGI ARC20/CompressedBG 的解包解码器；BGI 脚本对照可研究 Bgi_asdis / EthornellTools / VNTextPatch；`msg_tool` 文档声称支持 BGI ARC v2 及 BGI 音频，但**必须用本机具体资源先验证，不代表已安装或已成功解包**。
- 不直接套用旧补丁的可执行文件和字体；需要明确字体分发授权、后日谈补丁覆盖依赖及许可证。

## 6. 风险登记（风险高≠不可行）

| 风险 | 级别 | 验证与对策 |
|---|---|---|
| 同名资源不是同内容（剧情、语音、CG） | 高 | 哈希、尺寸、波形/时长和关键节点人工复核；不同版本差异显式登记 |
| BGI 脚本缺少能等价表达的 ONS 演出操作 | 高 | 复用 `f_` 包装层并做专门兼容映射；不支持效果单独替代 |
| 高清贴图与旧脚本逻辑像素不一致 | 高 | 800×600 与新的 4:3 逻辑坐标双方案 POC；遮罩/移动/文字定位实测 |
| BGI bw 音频与 CompressedBG 解码兼容 | 中高 | 先取多种样本验证，失败换解码器，不进入全量迁移 |
| 内容完整性：旧版 125 个同名脚本内部仍可能不同 | 高 | 逐场景 diff 文字/命令/跳转，不能只凭脚本名称覆盖率判断完成 |
| 后日谈 exe 的内容与版本依赖 | 高 | 单独研究安装说明与文件差异，原 PC 版不直接改 |
| 超清图内存/解码耗时、视频异常 | 中高 | 按场景分辨率策略、缓存预算、逐片段性能测试 |
| NSP 与 SD 卡路径、存档与旧版冲突 | 中 | 保留旧版本快照、新版分开工作树/存档，实机安装回滚演练 |
| 许可限制与第三方汉化版权 | 高 | 优先私人、合法测试；对外发布之前确认著作权人与汉化作者许可 |
