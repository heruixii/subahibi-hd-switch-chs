# 第288轮：字幕乱码根因定位与 P1106 三字节补丁（首次修正文本层前导字节判定）

## 两个根因

1. **759 条旁白侧载文件从未安装**。`P1446` 的 759 条覆盖层从
   `sdmc:/switch/subahibi_pc_native_hd_qa/chs/unvoiced_unique_voice_anchor_cp932_gbk_759.bin` 读取，
   设备 chs 目录此前只有 2 个文件（18092 字典 + 26 句开场），759 文件缺失 → `p1442Ready=0` → 旁白全部回退日文。
2. **文本层前导字节判定没跟着 GBK 走**。`P546` 只扩展了 OS 层 `OsCommon_SjisIsLead`，
   而排版/绘字用的 `core/strutil.c` 的 `SjisIsLead` 仍是原版：仅 0x81–0x9F、0xE0–0xFF 视为双字节。
   GBK 前导字节 0xA1–0xDF（如“星”=D0 C7）被拆成两个单字节字符，逐字节送字体层 → 乱码。

证据：`P1095_ISOLATED_148.../src_core_strutil_aarch64.o` 反汇编中 `SjisGetChar` 内联判定为
`sub wX,wY,#0xa0; cmp wX,#0x40; b.cc`（0xA0–0xDF 判为单字节）。合并对象 `P1134...o` 中该模式恰好 3 处：
`SjisGetChar+0x14`、`IsKinsokuChar+0x110`、`TextGetCharMode+0x4C`。

## 本轮处置

- **侧载**：把 `SBCHS003`（80,307 B，SHA256 `60dcbe6e…0a47d1b9`）以准确文件名装入设备 `chs/`，现 chs = 3 项。
- **补丁**：在 P1105 NRO 中把 3 处 `cmp wX,#0x40` 改为 `cmp wX,#0x00`（imm12 0x40→0x00），
  即仅 0xA0 保留单字节，0xA1–0xFE 全部按双字节。整文件仅 3 字节差异（0x2F1CE、0x2F6FE、0x2F876）。
- 新 NRO：`Subahibi_PC1647_P1106_CJK_LEADFIX_NOT_VERIFIED.nro`，8,122,368 B，
