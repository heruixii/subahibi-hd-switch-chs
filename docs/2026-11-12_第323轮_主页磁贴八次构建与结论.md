# P1487 主页磁贴：八次构建与结论（AMS 22.0.0 上不可行）

日期：2026-11-12
设备：Switch，Atmosphere **1.11.0** / 固件 **22.0.0** / emuMMC / sys-patch 1.6.0（`ams_keygen=21`）

## 结论先行

**Nro2Nsp 这一代 forwarder 依赖的 hbloader 链式加载，在这台机器的 AMS 22.0.0 上不工作。**
换 npdm、换 keygen、换 NRO 封装、换启动器二进制，八种组合全部失败。失效点是启动器本身，不是汉化、不是签名补丁、不是 NRO 内容。

**处置**：停止磁贴路线；已清理 SD 上的全部测试文件；系统里两个测试标题需手动删除；游戏与汉化维持 hbmenu 启动，功能完好。

## 排查证据

### 签名补丁完全正常（`config/sys-patch/log.ini`）

```
fw_version=22.0.0   ams_version=1.11.0   ams_keygen=21   is_emummc=1
fs : noncasigchk_17.0.0+  = Patched (sys-patch)
     nocntchk_19.0.0+     = Patched (sys-patch)
ldr: noacidsigchk_10.0.0+ = Patched (sys-patch)
es : es_22.0.0+           = Patched (sys-patch)
```

所以"没打签名补丁"这个假设一开始就不成立。用户机器上其它自制标题（植物大战僵尸）能启动，也印证这一点。

### 关键排除项

| 假设 | 验证方式 | 结果 |
|---|---|---|
| 缺 ticket | 结构对比，与 Nro2Nsp 原生产物一致（都是 3 个 NCA、无 tik） | 不是原因 |
| 签名补丁缺失 | 读 sys-patch 日志 | 全部 Patched，不是原因 |
| keygen 不匹配 | 用 `--keygeneration 21` 重建 | 仍失败，不是原因 |
| NRO 格式异常 | `hbmenu.nro` 与游戏 NRO 头部逐字节对比：**同样的 16 字节 `HOMEBREW` 前缀、同样 NRO0 在 0x10** | 前缀是这套工具链的标准封装，不是问题 |
| 安装位置 | `Nintendo/Contents/registered` 为空 → 装在 NAND | 不是原因 |

### 为什么 Nro2Nsp 的 GUI 一直"卡住"

枚举窗口发现 `Form2`（"Building.... Please wait"）挂着，但子进程 `hacbrewpack.exe` 的 **CPU 占用为 0** —— 不是慢，是 Nro2Nsp 没读完它的 stdout，管道写满后死锁。直接调用同一个 `hacbrewpack.exe` 几秒就完成。所以自动化必须绕开 GUI 直调 packer。

## 如果以后还要做磁贴

必须换一条**支持 AMS 22 的 forwarder 工具链**，而不是继续调 Nro2Nsp 的参数。候选方向：

1. 2025 年后仍在维护的 forwarder 生成器（内置新式 NPDM 与链式加载实现）
2. 用 devkitPro + hacpack 自行构建并**完整签名**（需含 `eticket_rsa_*` 的完整 keyset）
3. 主机端工具（如 hacBrewPackLZ 的 NRO 版）在 Switch 上直接生成

判断标准先看一条：**任何新工具产出的 NSP，先用它转发 `hbmenu.nro` 做对照** —— 能打开 hbmenu 才说明链路成立，再动游戏本体。这一步能避免反复强制关机。

## 用户体验教训

黑屏 + "正在关闭"卡死时，只能长按电源 12 秒硬断电。为避免反复重启：

- 判定失败前先等 25 秒（加载慢 ≠ 死）
- 退出先试短按电源休眠再唤醒
- 需要重启用长按电源 3 秒 → 电源选项 → 重启
- 任何 forwarder 测试前，先用 `hbmenu.nro` 做对照
