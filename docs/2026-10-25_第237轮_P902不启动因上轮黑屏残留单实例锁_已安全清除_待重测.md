# 第237轮：P902 启动失败定位为残留单实例锁，已恢复

2026-10-25 用户报告 P902「无法进入游戏」。DBI仍在线，经真实Switch SD日志只读回收：P839显示Game EngineMain进入并返回，最新P845日志停在 `E04 FAIL named instance lock or lock exists`，没有新P853 VM内容，P859 SHA不变。因此本次P902尚未执行到原版VM，也就不能判定上一轮GPU NULL DC修复无效。

经源码交叉核对真实P919 `OS_InstanceMutexCreate`通过 `mkdir(0700)` 以唯一目录 `sdmc:/switch/subahibi_pc_native_hd_qa/locks/.ns_subahibi_single_instance_qa.lock` 持有跨进程锁；原运行到结尾 `OS_InstanceMutexRelease`才调用rmdir。用户上轮P897黑屏后非正常关闭，可能残留锁。P1110 `OS_NamedMutexExists`对该目录存在时确实保持fail-closed，属于启动保护机制，不可直接绕过。

新建仅只读原生WPD枚举程序P1234并在用户重新进入DBI后实机验证：私人SD owner根包含精确10项，55份story资源、UserData、存档、font和唯一P902 NRO均在，`locks`仅有恰好一个名为 `.ns_subahibi_single_instance_qa.lock` 的对象且内部为空（0项）。随后生成P1235执行精确目标的 `PORTABLE_DEVICE_DELETE_NO_RECURSION`，预检dry-run成功、commit返回0。删除对象仅为一个空的原子锁目录，未碰玩家Save、字体、原商业媒体或其他锁。之后再次只读WPD验证 `P906_LOCKS_CHILDREN=0`，P902 NRO仍8093696字节且源/设备回读SHA一致 `479f4f2ab18768b1063e71d3b6ce9727ac415b87666923897169d82d656c3b4e`。本轮未修改P902 NRO。
